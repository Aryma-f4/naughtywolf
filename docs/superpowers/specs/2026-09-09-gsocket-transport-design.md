# GSocket Transport Design

## Goal

Add an opt-in GSocket transport to NaughtyWolf's existing authenticated C2 protocol so payloads generated by the web portal can connect through `gs-netcat` and appear in the portal callback workspace.

## Architecture

NaughtyWolf remains the protocol endpoint. GSocket only supplies a transparent TCP tunnel. The portal exposes the existing sealed C2 envelope protocol on a loopback raw-TCP listener, and a `gs-netcat` listener forwards its Global Socket connection to that port. A generated GSocket implant starts a local `gs-netcat` forward and connects its normal length-framed TCP transport to the forward.

The portal database is the authoritative callback and task store for portal-generated payloads. HTTP `/c2/checkin` and raw TCP both call one repository-backed sealed-envelope processor, so the two transports produce identical callback and task behavior.

## Payload profile

The payload wizard adds a GSocket secret field when `gs` is selected. The existing `NW_PSK` continues to authenticate and encrypt NaughtyWolf envelopes. The GSocket secret identifies and protects the tunnel and must remain a separate value.

The encrypted build configuration becomes a versioned object containing the endpoint, NaughtyWolf PSK, and optional GSocket settings. Old two-field configuration blobs remain readable. A GSocket endpoint uses `gs://127.0.0.1:<local-port>`; its secret is stored in the optional settings rather than embedded in the URL.

The implant invokes `gs-netcat` directly with `tokio::process::Command`; it never uses a command shell and never downloads or installs software. The executable defaults to `gs-netcat` on `PATH` and can be overridden with `NW_GS_NETCAT`. Failure to find or start it is reported through logs and retry behavior. The child is killed when the transport is dropped.

## Portal transport

`NAUGHTYWOLF_TCP_BIND` enables the portal raw TCP listener and defaults to no listener outside the GSocket compose profile. Each connection accepts one `[u32 big-endian length][sealed envelope]` request and returns one frame. Frames larger than 8 MiB are rejected.

The repository-backed processor performs the same PSK registration, ephemeral X25519 session-key derivation, callback update, task delivery, and result storage currently used by the portal HTTP C2 routes. It returns `PollReply` so it is wire-compatible with `nw-implant`. Task UUIDs are preserved from database enqueue through implant result delivery.

## GSocket server adapter

The Coolify/native compose file gains an opt-in `gsocket` service. It runs `gs-netcat -s <GS_SECRET> -l -d c2 -p <raw-port>` and connects only to the C2 service's private Docker network. The raw TCP listener is not published to the host by default. `GS_SECRET` must be explicitly configured; no public one-line installer or reverse-login shell is generated.

## UI and metadata

Selecting GSocket reveals the tunnel secret and local forward port, updates the review card, and explains the `gs-netcat` prerequisite. Payload metadata records the protocol and local port but never renders either secret. Callback rows record `gs` as their protocol when registration arrives on the raw TCP/GSocket listener.

## Validation

- Unit tests cover versioned config compatibility, secret validation, endpoint parsing, and redaction.
- Portal tests cover sealed register/poll over the repository processor and raw TCP framing.
- Implant tests use a fake `gs-netcat` executable to verify argument construction, startup reuse, missing-binary errors, and child cleanup without contacting the public relay.
- An end-to-end loopback test proves a generated GSocket profile registers in the portal callback database through a transparent local TCP proxy.
- Docker Compose configuration is rendered and checked without requiring a live GSocket relay.

## Constraints

- Do not remove or change HTTP, HTTPS, raw TCP, DNS, or SMB features.
- Do not execute through a shell, download GSocket at runtime, or install persistence.
- Keep `NW_PSK` and `GS_SECRET` distinct and redact both from UI summaries and logs.
- Bind the portal raw TCP listener to a private or loopback interface by default.
- Keep existing build metadata readable.
